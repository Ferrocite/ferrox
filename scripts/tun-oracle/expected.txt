# The dial set the pinned reference stack produces from script.txt. One
# `DIAL <target> <hex payload>` per TCP flow (payload read to connection EOF)
# and one `UDIAL <target> <hex datagram>` per delivered UDP datagram. `main.rs`
# records this file by running the stream through smoltcp 0.12 — the userspace
# stack the pinned zero-tun `zero-tun` crate builds on — so the bytes here come
# from a reference run, not from this tree. The TCP convention it pins (dial per
# flow on handshake, deliver the reassembled payload in order, EOF at FIN) is
# also what xray's proxy/tun/tcp_lightweight.go does at `input`, `receive` and
# `ReadMultiBuffer`; the UDP half pins that a datagram is delivered whole and
# alone — two bodies to one port are two lines, never one concatenated stream.
