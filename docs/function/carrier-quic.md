# The QUIC carrier

QUIC carried VLESS only as a client row; the **server role now exists** and serves a `vless` inbound on `security: tls` with a certificate (`serve_vless_quic`, `proxy.rs:1352`). Each bidirectional stream is one VLESS TCP session: the UUID check, the empty-flow requirement and the TCP target dial happen inside `serve_vless_quic`, and a stranger or a UDP/mux offer closes the stream before anything is relayed. The ALPN is the default lane one (`h3`).

quiche is the default QUIC stack for this rung, and that is a rule rather than a preference: whenever a rung needs QUIC and quiche is feasible, quiche. The pin `upstream/quiche` at `3fc9bc1c` exists for reading.

The one thing this carrier actually decides is how many handshakes a connection costs. A naive dialer handshakes per stream; this one dials once per server and shares the connection, so N streams on one server cost one handshake, not N — including the N that arrive one after another rather than at once. `quic_pool_shares_one_connection_between_two_streams` gates the overlapping half, `a_lane_outlives_its_leases_and_the_next_flow_rides_it` the sequential half.

A lane that outlives its last lease is parked, not closed: `pump` ends its own thread when the socket is quiet and no lease rides the table, and the connection, its stream ids and its bound socket stay in the pool for the next flow. The next lease restarts exactly one pump, taking the flag on the same lock the thread left it on. Two bounds keep a parked lane from becoming a pin: the edge's own idle timeout, advanced by one `on_timeout` call at lookup so the gap is quiche's arithmetic rather than a budget of ours, and `flows-per-lane-before-it-is-handed-back`, which is inside the 100-stream grant `MAX_STREAMS` advertises.

Every socket `bind_datagram` opens — a lane's, hysteria's client and the server's listen socket — asks for a receive buffer at bind, one `setsockopt` each and off the hot path, because a parked socket is the only thing holding what the edge sent while no pump owned it, and a Windows default (64 KB) drops it. The ask is read back rather than assumed; `receive-buffer-floor-bytes-armed-per-lane` is the floor it has to land as.

The other buffer a lane carries is quiche's own, and it is the bigger one: every byte the edge delivers parks in this process until the application reads it, and the credit the lane advertises is the size of that parking lot. `tune` and `quiche_config` now name the ceiling as well as the opening credit — `MAX_DATA` 2 MiB across a connection, `MAX_STREAM_DATA` 1 MiB per stream, with `set_max_connection_window` and `set_max_stream_window` clamping quiche's auto-tuning to the same numbers, because a window that only ever grows is a window that was never capped. `quic-bytes-parked-per-unread-stream` and `quic-bytes-parked-per-unread-connection` are that cap measured from the edge's side by `an_edge_cannot_park_more_than_the_window_unread`: a writer addressing a lane that never reads stops at exactly 1 MiB on one stream, at exactly 2 MiB across the connection (the third stream finds no credit at all), and the credit rolls back when the lane drains what was parked — a capped window is a rolling one, not a throttled one. The gate has to tell flow control from pacing to see this: quiche caps a `stream_send` by congestion-control capacity as well as by credit (`update_tx_cap` takes the tighter of the two), so the test ferries packets between writes — transport acks keep the send window open while an unread lane keeps the credit closed — and calls a writer stalled for forty whole ferry rounds flow-control-blocked rather than paced.

The hand-back itself is a pool decision, not a protocol one: a lane that has lent its whole grant leaves the pool's table so the caller's `or_else` dials a fresh one, and only a lane no lease rides is given the `done` frame. `a_lane_that_lent_its_whole_grant_of_flows_is_handed_back` asserts both halves — the entry gone from the pool, and the flow that stayed on it still carrying bytes, which is the witness that no goodbye was sent over it.

Roots are required. A dial without `caCertFile` returns `None` and sends nothing, which `quic_outbound_reads_ca_cert_file` covers — the refusal is deliberate, not a fallback to the system store.

## Time

**Not measured yet.** QUIC throughput belongs to `.github/workflows/speedtest.yml`, which is dispatch-only because it downloads a real target per config per core; a number from a machine behind a VPN measures the tunnel. `.github/workflows/foxy-relay.yml`'s `Lane durations` table cannot see a parked lane at all: it restarts the lane for every carrier row (`a port per carrier, because a lane that outlives its stop still holds the port`) and takes one flow per row, so every row is a cold lane and a spent handshake. What that table can gate is the arm a cold lane pays at bind, and the h3 rows are where it would show: 1.00 MB/s against a 5.91 MB/s control on macOS, 1.84 against 3.00 on Windows, 2.22 against 5.49 on Ubuntu. A sequential-flow number needs a row that takes N flows on one lane; no such row exists yet, so the reuse is gated by pointer identity in `a_lane_outlives_its_leases_and_the_next_flow_rides_it` and its rate is an open claim. The one wall-clock number this page does hold is the harness's rather than the lane's: `quic_pool_shares_one_connection_between_two_streams` costs 0.66 s now against the 120.12 s it measured when its edge left on its bound instead of on the FINs it had already read, and every `ci` test job was paying that on each platform.

## What we removed

- **A handshake per stream.** sing-box pools QUIC connections the same way; the difference is that this tree makes the pool the *only* way in, so there is no per-stream dial path to regress into. Gates: `quic_pool_shares_one_connection_between_two_streams`, `sixteen_flows_at_once_all_arrive_whole`.
- **The 24 MiB an edge could spend against the process.** The lane advertised `initial_max_data` 10,000,000 and one million per stream, and named no ceiling, so quiche's auto-tuning pulled the receive window toward its built-in 24 MiB and an edge writing to a lane that had not read yet got to spend that much of this process's heap — the 22 MB the live lane showed. The credit is 2 MiB and 1 MiB now, and the auto-tuning ceiling is the same numbers, each set beside the opening credit in the two places configs are built (`tune`, `quiche_config`) and in the test builders that read the same constants. `an_edge_cannot_park_more_than_the_window_unread` is the witness, and its two rows above are what it observes; the rolling half of the test is what says the cap is a window and not a rate limit. What was **not** removed: quiche's copy of every delivered byte into its stream buffer — that copy is the floor of a userspace QUIC stack — and the auto-tuning itself, which still grows the window on time, only up to two megabytes rather than twenty-four.
- **Three of every four lock passes on the drain.** The pump handed quiche's stream buffers to the waiting streams in 8 KiB chunks and the uplink read the client in 8 KiB chunks, and every chunk paid the connection mutex twice — once to take it, once for the egress sweep behind it. Both chunks are 32 KiB now: same bytes in the same order, one quarter the trips through the lock. No row carries this, because a loopback test cannot see an operation count — `scripts/method-ops.txt` publishes `quic::pump` and the `ops.yml` artefact is where the shrink will show, on a Linux runner rather than here.
- **A silent trust fallback.** A dial with no `caCertFile` sends nothing rather than reaching for the platform store. A security property, not a speed one, and it belongs here because it is a refusal that costs a connection.
- **A PEM buffer that grew, and one that was copied.** `der_to_pem` opened on `Vec::new()` and let each `extend_from_slice` double it, re-copying the prefix every time; `serve_config` and `quiche_config` then built each certificate as its own `Vec` and copied it into the chain. One `pem_capacity` reservation now sizes the whole buffer and `append_pem` writes blocks straight into it. `a_pem_buffer_is_reserved_to_its_exact_length` gates the reservation (`len == capacity`, so no realloc fired), `appending_into_a_reserved_buffer_does_not_move_it` proves the removed copy by pointer identity, and `pem_survives_the_pad_and_wrap_boundaries` shows the bytes did not change.
- **Three zero passes per datagram.** `flush_egress`, `pump_once` and a relayed `Datagram::send_to` each opened a zeroed array — 1350, 1350, 1372 bytes — that the packet or the read then overwrote in full. All three take `quic::Unfilled` now, a stack array of `MaybeUninit<u8>`, so the first store to a byte is the writer's. A relay frame's two reserved bytes and fragment flag are what the hop reads before the target, so those three are filled explicitly, and `a_relayed_datagram_frames_its_target_ahead_of_its_payload` asserts the whole frame and goes red if that fill changes. The removal is checked in machine code: the `mov w1, #0x546`/`#0x55c` + `bl` zeroing pair is gone from every frame that carried it, and `send_to` inlines into three of them, so the release binary drops from 9 sites to 4. It carries no counts row — the filter `scripts/expected-ops.txt` blesses never sends a datagram, and a loopback test sees packets, not the stores behind them — but `scripts/method-ops.txt` now publishes `flush_egress` and `pump_once`, where a callee's inclusive cost would show the stores. The bytes did not change: the QUIC echo, SOCKS-hop and foxy tests check the same packets end to end.
- **A pump that visited the socket once per datagram.** A 16 KiB h3 DATA frame arrives as a dozen packets, and each of them used to be one whole visit: a `setsockopt` to arm the wait, one `recvfrom`, one egress sweep under the lock, and only then the next. The pump now takes up to `PUMP_BURST` (64) datagrams in the visit it is already in and sweeps once, and the armed wait expires into the same stop an empty queue gives, so a busy socket cannot hold the lock past the burst. The drain is bounded twice, by two different clocks: `PUMP_BURST` caps how many datagrams one visit takes, and after the packet the visit waited for, the arm drops to `PUMP_TAIL` (1 ms) so the rest of the drain sweeps only what the queue already holds. The callers hand this function their whole remaining budget as `wait` — `stream_recv_exact` and `send_credit_wait` both pass the deadline that is left — and the first shape of this change kept that arm across the drain, so it held a flow for seconds after the packet it came for had landed: the `ferrox-app` suite went from 134.9 s to 1014 s and `quic_serves_two_streams_on_one_connection` failed. What the fix costs, named: one extra `setsockopt` and up to a millisecond on a visit that receives; a visit that receives nothing pays exactly what it paid before. `a_pump_that_absorbs_its_burst_does_not_hold_the_wait_it_armed` is the bound on the hold (one second armed, a quarter of it is the ceiling) and `one_pump_absorbs_the_whole_datagram_burst_on_the_socket` reads the queue, not the bytes: three datagrams on the socket, one pump, and a fourth read must find nothing. Each is red on the shape it names. CI's `ops` artefact is the witness with exact numbers, and it is informational rather than a blessed row: for the one test that carries 1 MB down an h3 lane it reads `recvfrom 617 → 242`, `sendto 619 → 222`, `setsockopt 621 → 65`, `getsockname 161 → 4` and `foxy::H3::read` Ir `140,460 → 119,175` against the pre-drain tip `737c6bf`, which is 2,036 syscalls for those bytes down to 551 with no row risen. The live relay cannot see a change this size: three samples of each ref on each OS put `carrier h3` inside the spread of the same ref run twice, with main's own macOS readings swinging 0.51–1.85 MiB/s and the drain's at 0.46–0.56.
- **The wait each holder remembered for itself.** `SO_RCVTIMEO` is a property of the file description, not of the handle: a `try_clone` shares it, so two handles over one socket arm the same clock. `pump` polls at `PUMP_POLL` (500 ms) on the socket `lend` cloned for its thread, while a flow's `pump_once` arms that same description at its own timer and leaves it at `PUMP_TAIL` (1 ms) once a burst lands. Each side used to keep its own note of what it had armed, so the pump's next turn read its note, said "500 ms already applied", and waited on the millisecond the flow had left behind: a lane's pump waking a hundred times a second, each wake taking the connection mutex every other session on the lane waits on, instead of sleeping out its poll. The note is one cell inside `Datagram` now, behind an `Arc` that `try_clone` passes on, so a read through any handle arms only what the description does not already carry. `a_clone_carries_the_socket_it_was_cloned_from_one_arm_record` pins the sharing by pointer identity — the cell is one object, not two that happen to agree — and `a_wait_undone_by_another_handle_is_armed_again_before_the_read` is the hang: one handle asks 400 ms, a second arms 4 ms through the same description, and the first read must still get its 400; it returns at 4.5 ms on the per-handle shape. What this costs, named: an arm the old note skipped is paid now, so a socket with two holders on different budgets makes one `setsockopt` each time the value moves instead of none, and every datagram socket carries one small shared cell. What is kept is the dedupe that made the note worth having, and it is now correct for both sides: `pump_once` on a drive loop whose timer has not moved re-arms nothing. No blessed row carries any of this — the gate that can see a `setsockopt` is CI's `ops` artefact, informational, and the `setsockopt` line quoted above (65 for the 1 MB h3 read) is what it will be read against.
- **A pool entry pinned by a flow that had already ended.** A stream id was reserved in the pooled table's `opening` set and given back only by a caller that remembered `release_stream(dial, id)`: a failed open, a front that returned early, a CONNECT-IP lane the edge granted no address to and every UDP lane left it behind, and an id behind keeps the entry, its `quiche::Connection` and its bound socket alive for the life of the process. `PooledStream` now carries the entry it came from and its `Drop` pays the table back, so `release_stream`, the `(dial, id)` pairs threaded through the caller's types and the `PooledDatagram` wrapper that held one are gone. What the give-back is now checked by is the park: `pump` ends its thread only over a table no lease rides, so `a_lane_outlives_its_leases_and_the_next_flow_rides_it` goes red on an id that was never returned. Not counted: the second `QuicDial`, root list included, that a successful open built just to carry the release, because no gate here measures allocations per open.
- **A handshake per flow, and a thread per idle lane.** `leave_session` closed the pooled connection with a `done` frame and cut the pool entry when the last lease ended, so every flow after the first re-handshaked against the same edge: the page's own claim, `handshakes-per-server 1`, held only for streams that overlapped in time, and on a foxy lane, where one flow is one request, that is every flow. `quic::pump` parks instead — the thread ends, the flag says so under the same lock the next lease takes it on, and the connection, its stream ids and its bound socket stay in the pool — and `leave_session` is down to the id it came to return. Three flows on one handshake is `a_lane_outlives_its_leases_and_the_next_flow_rides_it`, which asserts the connection by pointer identity rather than by another dial; the bound on how long a lane may be kept is `a_lane_that_lent_its_whole_grant_of_flows_is_handed_back`. A parked lane that the edge let go is found by quiche's own idle timer, read at lookup with one `on_timeout` call, so no constant of ours guesses the peer's patience; a lane whose grant is spent leaves the pool at the next lookup, and only gets the `done` frame when nothing rides it. What this costs, named: one `Mutex::lock` and one timer pass per lease on a warm lane, one `thread::spawn` per park rather than per dial, a `try_clone` of the lane's socket that only a parked lane pays for, and a spent lane that still carries flows leaving the pool without a goodbye — its last lease parks it and the connection goes with the leases that held it. Parking is the lane-level version of the seam [`docs/concurrency.md`](../concurrency.md) proposes tree-wide: a parked lane already frees its thread, and the poller would free the one a leg holds while blocked mid-read.

- **A `sendto` per datagram out of a sweep.** One `flush_egress` call drains everything quiche is ready to hand over, and on a plain lane that is a burst rather than a packet: a 32 KiB `stream_send` queues about ten datagrams behind each other, and every one of them used to be a syscall of its own. The sweep now writes each packet straight into its own slot of an eight-deep `mmsghdr` array — quiche's own store is the only copy and the batch adds none — addresses each slot with the peer quiche named for that packet, and hands the set to one `sendmmsg`, retried from the first message the kernel did not take, then fills again while quiche still has packets. `an_egress_sweep_drains_its_whole_queue` is the witness and it is the exact one: immediately after the call the connection is asked whether it still has a datagram ready, so a sweep that stopped at its slots goes red instead of losing the tail to a retransmission nobody scheduled; the same test handshakes the lane *through* the batched path and checks that what the peer reads is the frame's prefix, in order, whole. What the batch does not ride on, named: a gecko fragment, a hop, an obfuscation or a relay frame each wrap `send_to` in work that is per-datagram by shape, so those lanes keep the loop, and every platform but Linux keeps it too, because `sendmmsg` is a Linux call. What it costs: eight `Unfilled` datagram buffers — some 11 KiB of the sweep's own stack, unwritten until a packet lands in one — where the loop reused one, a `sockaddr_storage` and a header wired per packet the sweep takes, and a refusal now drops the batch it was aimed at rather than the packet it was aimed at, which quiche retransmits either way. No counts row carries the shrink: the checker that can see a `sendto` is CI's `ops` artefact, informational, and the gate above sees datagrams, not the calls behind them.
- **A 120-second wait standing where a FIN assertion belongs.** `quic_concurrent_echo_server` — the edge `quic_pool_shares_one_connection_between_two_streams` dials — could leave only on `conn.is_closed()` or its `QUIC_TEST_TIMEOUT` bound, and a lane that parked after its last lease closes no connection by design, so that test ran out its budget every run: 120.12 s measured single-threaded, and because it holds `quic_serial` for all of it, the four QUIC tests queued behind each printed "has been running for over 60 seconds" while it spun. The edge now leaves once every stream it accepted has read its FIN, and that count is asserted, so `streams-left-open-per-flow 0` is the FIN `uplink_stream` already sent at the end of every lease and nothing had ever checked. The gate was proven to bite: with that `stream_send(id, &[], true)` turned into a non-final send the edge reads no FIN, the bound fires, and the row answers `0` against the `2` it must reach. Same test after the fix: 0.66 s — the ~120 s this cut is per `ci` test job, on each of the three platforms. What was not removed: the bound, which is now the failure path rather than the exit, and the parked lane's silence about the connection itself, which still ends only when its grant is spent or quiche's idle timer says the edge let go.
- **A `dup` per burst on the downlink.** `hand_off` looked the flow's socket up in the pooled table and `try_clone`d it, because the write had to happen after the connection lock went back — the pump cannot block on one flow's upstream while every other session waits on the mutex — and a write needs an owned handle. So every visit in which a stream read as non-empty paid a `dup` (one syscall on Linux, two where the cloexec `fcntl` is separate) for a handle that was thrown away lines later, and paid it *inside* the lane's table lock, which every `lend` and `leave_session` on that lane waits for. The table now holds each flow's handle behind an `Arc` and the drain writes through `&Connection`, which `conn.rs` already implements for the relay's by-reference legs, so a burst costs a refcount instead of a syscall. What it costs, named: one `Arc` allocation per flow, where the map used to keep the `Connection` inline, and a flow's socket outlives its table entry by as long as the pump still has it in hand — which is the write it came for, not a queue. What was not removed: the `dup` `lend` makes to put that handle in the table and the one `uplink_stream` makes to read through its own handle, both once per flow, nor the `try_clone` of the lane's UDP socket a flow flushes with. The checker that can see this is CI's `ops` artefact, informational, and the `quic::hand_off` frame `scripts/method-ops.txt` now publishes; a loopback test sees the echo, not the calls behind it, so no blessed count row carries the shrink.
Not removed, and named rather than claimed: `pump`'s per-connection scratch, `pump_once`'s `setsockopt` on every visit (a receiving visit pays two arms, the wait and the `PUMP_TAIL`; the arms a shared record makes redundant are still deduped — one record per file description now rather than one per holder, which is what the wait that was being missed cost; the burst above cuts the *visits*, and with them the arms, not the arm one visit needs), quiche's packet build inside `send_on_path`, and 0-RTT, connection migration, key updates and `recvmmsg` batched datagram reads — those are quiche's, not this tree's. The park is not instant either: `PUMP_POLL` is how long an idle lane can still hold its thread, and a lane parked past the edge's idle timeout is only found when the next lease looks at it. And the window cap trades a bound for a rate: a lane that reads slower than one 2 MiB round trip per window now paces its edge, which is what the roll-back half of the gate shows it survives; on a fat line the old 24 MiB could absorb a longer stall before the writer felt it.
