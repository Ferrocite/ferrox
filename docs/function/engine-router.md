# Routing rules and the geosite/geoip assets

A rule is a set of selectors that must all hold, and one outbound tag the first match decides. A rule may instead name a `balancerTag`: the balancer draws a candidate from the outbound tags its selector prefixes match, ordered by tag as the reference handler manager sorts them, with `random` when no strategy is given and an atomic counter for `roundRobin`. `leastPing` and `leastLoad` read the snapshot the observatory publishes ([`engine-observatory`](engine-observatory.md)); with no snapshot, an unknown tag, or a selection the baselines reject, the `fallbackTag` and then the default outbound answer. A duplicate balancer tag, an unknown strategy, a selector that is not a list, and a rule naming a balancer no entry defines are startup refusals named by the offending field. When a rule names both an outbound tag and a balancer, the outbound wins, as the reference's selector does. The default is the first configured outbound — the reference's `defaultHandler`, tag or no tag — so a config that adds `routing` moves unmatched flows to that entry rather than to the protocol priority this tree used before. Every tag a rule names is built once, at startup; a tag no outbound carries, an outbound this tree cannot dial, and a missing asset file or code are startup refusals named by the thing that is missing, never inert rules.

A rule may also carry a `webhook`, the callback that fires once the rule has chosen the flow's lane: the event is POSTed on its own thread in the reference's `encoding/json` shape — `email`, `level`, `protocol`, `network`, `source`, `destination`, `originalTarget`, `routeTarget`, `inboundTag`, `inboundName`, `inboundLocal`, `outboundTag`, `ts`, in that order, a fact the flow does not carry as `null`, and the tag the lane actually took as `outboundTag` (a balancer's pick, which is what the reference's `GetTag` returns) — with `destination` the sniffed target, `originalTarget` the one the client asked for, and `routeTarget` only when a `routeOnly` sniffer left the dial alone. `url` is an `http://` or `https://` URL, or a socket path (`/path`, `/path:/http/path`, `@abstract`, `@@padded`, the last the padded abstract name the reference spells but its own dialer refuses); `headers` overwrites the JSON content type case-insensitively, as the reference's header `Set` does; `deduplication: N` sends at most one event per account email in N seconds. One five-second budget covers the dial, the TLS handshake and the reply; a status of 400 or above, a URL that does not parse and a dial that fails each write one line to stderr and end that event. An entry whose `url` is empty is no notifier, and a scripted config fires none, as the reference fires none on its script path. A SOCKS association that any reachable rule with a webhook could match is split into one lane per datagram, so every datagram's flow fires the event of the rule it hit; a collapsed association has no reachable webhook rule. A server inbound dials direct and never fires one, which is warned at startup rather than left silent.

A rule may also name `ruleSet` (or `rule_set`) tags. A set is a list of headless rules: every field a rule names must hold, a list field is an OR (`domain` is exact; `domain_suffix` matches subdomains and the apex, while a leading `.` makes that suffix match subdomains only), `type: logical` combines nested rules with `mode: and` or `mode: or`, and `invert` flips that rule alone; a known tag with no matching rule is a miss, not an error. Inline sets and `type: local` files are read as source JSON: `rules` is an array of headless rules, or the object is the native `{"domain": [...], "ip": [...]}` shape, with bare `domain` entries becoming suffixes. `format: binary` (an `.srs` container) and `type: remote` are refused by name, because the zlib container is not in this tree's dependency policy and nothing here fetches a set at runtime. A rule-set address is unknown until `IpIfNonMatch` resolves or the flow carries an address: the first pass reports `Unknown` only for sets whose other selectors already hold, which is what decides whether a lookup is owed.

`routing.script` is xray's Lua routing hook: a path, resolved against `xray.location.confdir`, `xray.location.config`, the working directory, the executable's directory and the asset locations, with symlinks followed and the resolved target required to be a regular `.lua` file, and the top level run once at startup so a syntax error stops the process before a listener opens. A script cannot be combined with `domainStrategy` or a non-empty `rules`; the reference refuses both, and so does this tree. Each decision runs `HandleRoute(ctx, inbound, sourcePort, targetPort, localPort, targetDomain, network, protocol, user, vlessRoute, skipDNSResolve)` in a pooled Lua state (`lua51`, at most 16 idle, a 6s instruction hook per call); `nil` or an empty tag leaves the default handler in place, a non-string tag or a third-value error fails the flow through the blackhole lane, and a string tag names the lane. `xray.router.PickOutbound` resolves a balancer with its fallback or an outbound tag that was configured or added after startup, `xray.dns.Query` uses the configured resolver, honours its v4/v6 flags and returns its TTL, `xray.dns.Servers` exposes each configured server by its `id` with its own `Query`, `xray.geodata` builds domain/address matchers over `geosite.dat`/`geoip.dat`, and `FindProcess` reports that process lookup is not carried; `xray.log` drops `Debug`/`Info` and writes `Warning`/`Error` to stderr.

The asset containers are xray's protobuf `GeoSiteList` and `GeoIPList`, decoded here with the same field walk the rest of the tree uses for xray's wire form. On Unix a container is read into an anonymous mapping rather than a heap buffer and unmapped when the parse ends, so a real `geoip.dat` is resident during startup, not for the life of the process; elsewhere it is a heap buffer. `geosite:CODE@attr@attr` keeps only the domains that carry **all** listed attributes; codes are compared case-insensitively and attributes are lowercased as the reference does. For addresses, a leading `!` on a rule toggles that rule's own reverse flag, twice toggles it back, and the positive and negative subsets OR together. A family that the negative set never names is not matched by its reverse — the reference's `max4`/`max6` sentinel — so a v4-only `!geoip:test` does not match a v6 address.

The top-level `geodata` block is the reference's asset refresh, and its build is where the reference checks the shape, so this tree checks it at startup before an outbound is dialled: `cron` is a robfig v3 standard expression — five whitespace-separated fields over minute, hour, day of month, month and day of week, with `*`/`?`, ranges, `/` steps, lists, three-letter names, the `@yearly`/`@annually`/`@monthly`/`@weekly`/`@daily`/`@midnight`/`@hourly` descriptors and `@every <Go duration>`, and a `TZ=`/`CRON_TZ=` prefix — `outbound` a string, and `assets` an array of `{url, file}` where the URL must be HTTPS with a host and the file a local, relative, regular file under an asset location, because the reference's `filesystem.StatAsset` and `url.ParseRequestURI` refuse anything else. A non-object entry and a malformed cron are refusals named by the offending field, while an unknown field is inert because the reference's JSON decoder leaves it inert too; the zone name of a `TZ=` prefix is not resolved here, so a zone the reference refuses still starts; a configured `cron` is accepted and then answered with one stderr line, because the staged download, the swap and the reload are not carried here and the files on disk are what runs.

Domain forms: `geosite:` / `ext:` / `ext-domain:` / `ext-site:`, `domain:` (suffix), `full:`, `regexp:`, `keyword:`, `dotless:`, and a plain value, which is a substring as in the reference. `ip:` / `source` / `localIP` take CIDRs, `geoip:`, `ext:` or `ext-ip:`. Ports accept a number or a comma/range string; `env:` is refused by name. `network` is `tcp` or `udp`; `unix` is refused by name. `localOS` is compared case-insensitively with `darwin` for macOS. `vlessRoute` is the route id a VLESS client sent; no flow this tree routes carries one, so the selector reads 0 exactly as the reference's context does off a non-VLESS inbound, and a list holding 0 matches every routed flow. `user` is an account email: a literal name or a `regexp:` pattern (the prefix must leave a pattern, as the reference's length check does), and a flow with no email never matches. An empty list is no selector at all, as the reference's `len > 0` check makes it, while a list whose entries are all empty or invalid patterns is a matcher that matches no account. `attrs` names an HTTP head: the plain-HTTP front sets `:method` uppercased, `:path` percent-decoded and stripped of its query, and every header but the hop-by-hop names and `host`, while the sniffer sets `:method` and `:path` as sent and every header it reads with the last of a repeated name winning; a configured key must be present and its unanchored `regexp` must match, keys are compared without regard to case, an empty object is no selector at all, a pattern that does not compile is a startup refusal, and a flow whose head was never read never matches; the script router does not carry the attributes, and a header name or value that is not UTF-8 is skipped where the reference keeps its bytes. `process` names the process that owns the client socket: `self/` is this process, `xray/` this executable, a trailing `/` a folder prefix, an interior `/` an absolute path, and anything else a basename with a trailing `.exe` trimmed; the owner is the kernel's answer — the socket's local address in `/proc/net/{tcp,tcp6,udp,udp6}` names an inode, the inode a pid, and the pid's executable its path — looked up once per flow and only when a rule names one, so a host without that table, every non-Linux host among them, carries the rule and matches nothing with it exactly as the reference's matcher does on a lookup error.

## What a flow carries

A flow has a network, a destination (a name stays a name; only a lane that carries no destination resolves it), a port, and — where the transport can answer them — the client's source address, the local address the inbound accepted on, the email of the account a socks or http front authenticated, the head an HTTP front or the sniffer read, and the process that owns the client socket. An absent field matches no rule, which is what keeps a selector from turning into an unconditional match. A rule with no selector is a catch-all, as the reference's selector-free rule is; a rule naming a selector this tree cannot evaluate is skipped with one warning, because applying its other selectors would widen it.

`AsIs` never looks a name up. `IpOnDemand` resolves on the first IP matcher the scan reaches, and the address test is last in a rule: a rule that already failed a source or local selector resolves nothing. `IpIfNonMatch` runs the match once, and only if nothing matched, the destination is a name, and a rule whose other selectors held still names an address set does it resolve and revisit just those rules. A literal destination and a table with no address rule both short-circuit the lookup: tests drive each path and count the resolver calls. A domain matcher hashes a name once from its last byte to its first, and each parent suffix falls out of that pass into an open-addressed probe that compares the string on a hit; the name itself is the last suffix probed, and an empty table is never probed. No label is allocated, and no byte of the name is hashed twice by one matcher.

## Lanes the transport cannot route

A server inbound in this tree dials direct whatever the rules say. Rather than ignore the table per flow, startup walks the rules that can reach the inbound (its tag, its network, the current OS) and requires each to target a freedom outbound — for a balancer, every candidate, its fallback and any active forced target; it stops at a rule that matches every flow on that tag, and otherwise requires the fallback to be freedom. Anything else refuses the config with the tag named.

A `tun` flow has no source or local address the rules could read. If any rule that could reach the tun tag names `source`, `sourcePort`, `localIP`, `localPort` or a rule set with a source selector, the config is refused naming that selector instead of letting the rule silently never match. A `process` rule is not refused: a tun flow carries no source address to look an owner up by, so the rule is carried and never holds. A routing script can still answer a tun flow by its destination, so a tun inbound is not refused for naming one.

A server inbound cannot evaluate a routing script, so a scripted config that would serve one is refused at startup naming the script; the reference's server path would otherwise route a dial it must keep direct.

A scripted config splits every SOCKS UDP association, because the script decides per datagram; a script error drops that datagram's flow instead of falling back. Otherwise a SOCKS UDP association whose reachable rules agree on one tag rides that tag's lane. When a per-destination selector (a domain, an address, a port) could send datagrams of the same association to different tags, the association is split: the outer relay asks the rules for each datagram's destination and forwards the frame to a lane, one per chosen tag, spawned on first use and reaped when its loop ends. A datagram whose destination picks a blackhole is dropped without opening a lane; a lane's replies travel back through the outer relay to the client. A rule that matches every datagram on the association still fixes a single lane, when all such rules agree with the fallback.

`flow-decision-allocations 0` is a rule table with no domain matcher: the scan reads ports and networks and allocates nothing. `host-lowercase-buffers-lowercase 0` is a domain match on the host as it arrived: the suffix and substring tables are stored lowercased, and a name that is already lowercase is borrowed rather than copied, which is the shape almost every client sends. `host-lowercase-buffers-mixed-case 1` is the same match on an uppercase name, where one buffer is the price of the comparison; the test asserts both counts, so a copy on the common path or a second copy on the mixed path fails them. That buffer belongs to the decision, not to a rule: `host-lowercase-buffers-mixed-case-two-rules 1` scans two domain rules and still pays one, where a per-rule copy would pay two. `geosite-shared-entry-copies 0` is pointer identity between the two rules' entries: a code named twice stores the same `Arc<str>` twice, not two decoded strings. `geosite-unwanted-code-allocations 0` and `geoip-unwanted-code-allocations 0` are the startup half: a container holding one large code and one named code parses in exactly the allocations of the named code alone, because the decoder reads an entry's code before its payload and skips every code the config did not name. `geosite-unrequested-attribute-allocations 0` is the same skip inside a named entry: a domain's attributes are decoded only when a rule asks for one with `@`, and an attribute key that is decoded is borrowed from the file rather than copied. `domain-table-reads-ip-if-non-match-candidate 1` is the second `IpIfNonMatch` pass: a rule whose other selectors already held before resolution is remembered, so the pass after resolution reads its address set and not its domain table again. `host-lowercase-buffers-before-a-domain-rule 0` is a rule that matches on its port before any table is consulted: the buffer is deferred until a table needs it, not bought at the top of the decision. `literal-route-allocations 0` is the same claim for a routed flow on an address: the plan borrows the chosen outbound and the decision touches no heap. `dns-lookups-per-rule-matched-name 0` and `dns-lookups-per-unmatched-name 1` are the two halves of `IpIfNonMatch` — a name a rule already matched is never resolved, and a name no rule matched is resolved exactly once before the second pass. `dns-lookups-ip-if-non-match-no-ip-rule 0` is the case the first half does not cover: no rule names an address set, so no address can turn the decision and the resolver is never called. `dns-lookups-ip-on-demand-source-failed 0` is the address test ordered last: a rule whose source selector already failed resolves nothing under `IPOnDemand`.

What was not removed: every configured outbound is built at startup when a script is present, as the reference's handler registry does, because a script may name any tag; each Lua state keeps its own globals, so a script that caches state sees the same state only within the pool slot it was given; a rule set is expanded into matchers at startup, so a large set costs its matcher for the life of the process; binary `.srs` sets and remote sets are not read at all. A geosite code is expanded into the rule's sets at startup, so a rule naming a large code pays that memory for the life of the process (the entries themselves are shared between rules that name the same code, but each rule keeps its own probe table); the container is still walked once per named code, and the named entry is read once, with a code that trails its payload deferred to the end of that entry; keywords build one Aho-Corasick automaton per rule that names them; the rule scan is linear in the number of rules, as the reference's first-match pass is; and a table past 256 rules re-tests the non-address selectors of the candidates in the second `IpIfNonMatch` pass, because their bits do not fit the stack mask. The registry keeps one outbound instance per named tag and clones the default for its own tag, so a lane's shared state is not duplicated.

## Time

No duration is claimed here. Benchmarks are CI-only in this tree, and the pinned routing references have no per-flow durations that a local run could compare without the tunnel this machine sits behind. The operation-count gate (`scripts/count-ops.sh`) needs valgrind, which does not exist for macOS/aarch64, so on this host the figure is `UNBLESSED` and the gate is the `ops.yml` artefact in CI.
